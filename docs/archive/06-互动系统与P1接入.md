## 一、互动反应系统

### 1.1 设计要点

互动是一层**临时覆盖**：触发后 1.5–3 秒内接管表情与台词，到期自动回落到当前工作状态。
反应期间不轮播多表情、不眨眼、气泡换色为「反应中」，且**计为「有操作」**——会重置空闲生气计时。

| 动作 | 触发条件 | 表情（按情绪标签） | 台词 |
|---|---|---|---|
| **单击 ×1** | 点一下 | `03`/`10` 开心1级 | ……诶？请、请别吓我。 |
| **单击 ×2** | 2.6 秒内再点 | `07` 开心1级 | 老师？……有什么事吗。 |
| **单击 ×3** | ↑ | `12`/`13` 开心2–3级 | ……嗯，我在的。 |
| **单击 ×4** | ↑ | `13`/`14` 开心3级 | ……嗯！这样、这样就完稿了……！ |
| **单击 ×5** | ↑ | `29`/`30` **害羞1–2级** | 呀……别、别一直戳我…… |
| **单击 ×6** | ↑ | `20`/`05` 生气1级 | ……老师，手，可以放开了吗。 |
| **单击 ×7** | ↑ | `18` **生气2级**（鼓脸撒娇） | （抱着稿子鼓着脸）……我又不是按钮。 |
| **单击 ×8** | ↑ | `16`/`17` 生气3级 | （别过脸去）……不理您了。 |
| **双击** | 一次连击中第 2 击 | `30`/`31` 害羞2级 | 诶、诶——！？……太、太近了。 |
| **长按 0.7s** | 按住不动 | `04`/`21` 困惑2级 | （愣住）……您、您在做什么。 |
| **按住拖动** | 位移 > 4px | `23`/`24` 惊讶1–2级 | 呀——！放、放我下来…… |
| **松开放下** | 拖拽后松手 | `22` 困惑3级 | （理了理衣角）……下次，先说一声。 |
| **悬停 1.6s** | 鼠标停在身上 | `36` 认真1级 | ……嗯？ |

### 1.2 一个踩过的坑（已修）

第一版用「**延迟 230ms 判定单击、以便识别双击**」的写法。结果是——**快速连点会被当成双击吞掉**，递进机制直接失效（点得越快越不动）。

改成：**单击即时响应**，双击仅作为「一次连击里补一次害羞插曲」存在（条件 `clickStreak === 2`，只在首次双击时生效，不打断递进）。

### 1.3 对外接口

```js
MiyoPet.react('click', 3);       // 外部触发：第 3 级单击反应
MiyoPet.react('dblclick');       // 也可直接触发某一动作
MiyoPet.liveLine();              // 当前反应台词，无反应返回 null
```

`react()` 统一走 `REACT` 表，**后续接真实事件（任务完成 / 报错）只需加一条表项**，不必改逻辑。

## 二、P1 数据通道（已打通并实测）

### 2.1 数据源

```
%USERPROFILE%\.workbuddy\tasks\<会话ID>\<任务ID>.json
单条： { "id":"10", "subject":"撰写完整 PRD", "status":"in_progress", ... }
status 实测取值： pending | in_progress | completed
```

| 桌宠提示 | 判定 |
|---|---|
| 正在处理 x 个任务中 | `in_progress` 计数 |
| 有 x 个任务需要确认 | `pending` 计数 |

> 会话里虽然暴露了本地端口，但 `/status` 一律 **401**，故**走读文件**——无需鉴权、结构稳定、写盘即更新。

### 2.2 两个脚本

| 文件 | 作用 |
|---|---|
| `scripts/task-status.js` | 零依赖读取模块。扫描任务目录 → 归类 → 汇总。可单跑：`node scripts/task-status.js` |
| `scripts/status-provider.js` | 状态桥。定时把汇总**原子写入** `status.json`（先写 `.tmp` 再 rename，避免桌宠读到半截 JSON） |

```bash
node scripts/status-provider.js                  # 默认写 v1/v2 两个目录，2 秒一次
node scripts/status-provider.js --interval 1000  # 改间隔
node scripts/status-provider.js --once           # 只跑一次
node scripts/status-provider.js --out prototype/v2/status.json
```

环境变量可覆盖数据源：`WORKBUDDY_HOME`、`WORKBUDDY_TASKS_DIR`。

### 2.3 实测结果

```
[status] 数据源   C:\Users\28679\.workbuddy\tasks
[status] 01:11:41  处理中 6  待确认 20  （任务总数 152）
```

写入 `prototype/v1/status.json` 与 `prototype/v2/status.json` 后，两版原型轮询自动生效——
**打开原型就能看到真实的「正在处理 6 个任务中 / 有 20 个任务需要确认」**。

## 三、Electron 透明置顶壳

```
electron/
  package.json   electron ^33 · npm start
  main.js        主进程：透明/无边框/置顶/不进任务栏 + 轮询任务目录 + 托盘
  preload.js     只暴露 window.petHost（onState / move / platform）
  icon.png       托盘图标（从立绘裁的头像，256×256 透明底）
```

**宿主模式**：页面检测到 `window.petHost` 会自动加上 `body.pet-only`——隐藏控制台与说明、桌面背景转透明、只留桌宠与气泡；
此时**拖动桌宠 = 移动窗口**（`petHost.move(dx,dy)` → 主进程 `setPosition`）。

手动预览宿主外观（无需 Electron）：浏览器打开 `prototype/v2/index.html?pet=1`。

### 运行

```bash
cd electron
npm install     # 会下载 Electron 运行时（约 100MB+，仅此一步较重）
npm start
```

> **本轮未执行 `npm install`** —— 它只下载运行时、不改变任何设计。需要真机跑桌面壳时说一声，我再装。

托盘菜单：显示/隐藏 · 始终置顶 · 重新载入 · 立即刷新任务数 · 退出。
（按您之前的交代，**不做开机自启**。）

### 5.4 排查过程中踩的坑（含已修项）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 快速连点不递进，反而像被吞掉 | 用「延迟 230ms 判定单击以识别双击」的写法，第二击会把待定单击取消 | 改为单击**即时响应**；双击只在 `clickStreak === 2` 时补一次插曲 |
| 2 | 运行时 `reactSeq is not defined` | **同一文件在一次消息里并行发两个 Edit → 丢更新**，v2 只落了声明、v1 只落了函数 | 同文件修改逐条串行；改后 `grep -rn reactSeq` 自查残留 |
| 3 | 自动化脚本报告「单击/双击/悬停未触发」 | `agent-browser eval` 传长 JS 静默不执行 + 跨调用取样抖动 | 测试脚本改由页面 `<script>` 加载；测试在页面内一次性编排 |
| 4 | 一度怀疑立绘不切换 | 实际是 170ms 淡入延迟造成的取样错位 | 用 `MutationObserver` + 80ms 采样器把时间线打出来，确认正常 |

```bash
cd electron

run.cmd         # Windows 直接双击也行
# 或
./run.sh        # Git Bash
```

主进程自检输出（实测）：

```
[miyo-pet] 页面就绪 {"ready":"complete","body":"pet-only","host":true,"hostFn":"function",
  "api":"function","mode":"pending","gallery":41,"reactBtns":9,
  "state":{"processing":6,"pending":20,"idleSec":0}}
```

含义：窗口已创建 · 页面进入**宿主模式**（只留桌宠）· `petHost` 桥可用 · 接口就绪 ·
**真实任务数已由主进程经 IPC 推到渲染进程**。

### 两个环境坑（已封进 run.cmd / run.sh）

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即报 `ipcMain ... reading 'on'` | 环境里 `ELECTRON_RUN_AS_NODE=1`，`require('electron')` 退化成普通 Node 模块，主进程拿不到 `app`/`ipcMain` | 启动器先**清空该变量** |
| GPU 进程反复退出 → `FATAL: GPU process isn't usable` | 没有可用硬件加速（远程桌面 / 无显卡驱动 / 受限会话） | `MIYO_GPU=off` 走软件渲染；受限会话再叠加 `MIYO_NO_SANDBOX=1` |

- 想恢复硬件加速：`MIYO_GPU=on`
- 退出：托盘菜单「退出」，或结束 `electron.exe` 进程
- 托盘菜单：显示/隐藏 · 始终置顶 · 重新载入 · 立即刷新任务数 · 退出
- 拖动桌宠 = 移动窗口（宿主模式下由 `petHost.move` 转成 `setPosition`）

> **两点我没能替老师确认的**：
> 1. 软件渲染下透明背景是否完全正确 —— 截屏 API 被安全策略拦截，无法核实。若窗口出现黑底，把 `MIYO_GPU` 改回 `on`。
> 2. **我没法把窗口留在后台** —— 我的执行环境会在命令结束时回收子进程，`nohup`／`disown` 也留不住
>    （实测进程确实会消失；且从 Bash 调 `cmd` 已被安全策略拦截，无法分离启动）。
>    所以**首次启动请老师自己双击一次 `run.cmd`**，之后它会一直开着，关掉前都在。
