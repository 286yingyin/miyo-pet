## 一、打包成可执行 exe

```bash
node scripts/build-exe.js
```

产物：**`dist/miyo-pet-win32-x64/miyo-pet.exe`**（双击即用，免安装）

| 项 | 值 |
|---|---|
| 总体积 | 334.7 MB（共 127 个文件） |
| 应用本体 | 105.2 MB（prototype v1+v2 的差分图为主 + 主进程 + 4 个状态脚本） |
| 运行时 | 229.6 MB（Electron 33.4.11 自身） |

> 后续又做了两处裁剪，属净收益：
> 1. **locales 精简 55 → 4**（只留 zh-CN / zh-TW / en-US / en-GB），省约 40 MB；
> 2. 说明文件改名 `启动说明.txt` → `READ-ME-FIRST.txt`（**文件名须纯 ASCII**，
>    否则单文件自解压包的 ANSI 指令文件会把它弄坏；文件内容仍是中文，不受影响）。

### 做法（**零下载**）

不依赖 electron-builder / electron-packager —— 它们都要再次联网拉运行时和签名工具。
这里**直接复用 `electron/node_modules/electron/dist`**：

1. 整份拷贝运行时 → `dist/miyo-pet-win32-x64/`
2. 删掉 `resources/default_app.asar`（默认应用）
3. 把应用放进 `resources/app/`，**保持与项目一致的层级**：

```
resources/app/
  package.json          { main: "electron/main.js" }
  electron/             main.js · paths.js · preload.js · icon.png
  scripts/              task-status.js · state-core.js · approval-status.js · change-log.js
  prototype/v1|v2/      index.html · settings.html · assets/
```

> 层级必须一致：`main.js` 里用 `../scripts/...` 与 `../prototype/<版本>/index.html`
> 定位资源，扁平化就会找不到。
>
> `scripts/` **只打包状态链路需要的 4 个模块**，开发用的
> `check.js / test-status.js / build-exe.js / build-portable.js / status-provider.js`
> 都不进包（它们不影响体积，但没必要跟着分发）。
4. `electron.exe` → 重命名 `miyo-pet.exe`

**踩到的坑**：`fs.cpSync(dir, dst, {recursive:true})` 在本环境里会**静默被杀**（进程 exit 127、无任何报错），
而 `fs.copyFileSync`（单文件）与 shell `cp -r` 都正常。→ 改成手写递归拷贝。

配置落在 `%APPDATA%\miyo-pet\config.json`（首次运行自动生成一份默认值）。

## 二、右键菜单与设置窗口

### 2.1 在桌宠上点右键

| 菜单项 | 说明 |
|---|---|
| 显示桌宠 / 隐藏桌宠 | 按当前可见状态切换文案 |
| **模式** ▸ | `v1 · 半身差分` / `v2 · 全身立绘`（单选，立即切换页面） |
| **设置…** | 打开设置窗口 |
| 始终置顶 | 勾选开关 |
| 退出 | 关掉程序 |

托盘图标的右键菜单含有同样几项（外加「重新载入」「立即刷新任务数」）。

### 2.2 设置窗口能调什么

- **桌宠版本**：v1（半身差分 948×948）/ v2（完整立绘 905×2477）
- **桌宠大小**：0.6×–1.6×，**窗口同步按比例缩放，右下角锚点不动**
- **始终置顶**
- **表情映射**：8 个状态（v2）/ 3 个状态（v1）各自关联**多张**差分图
  - 每行可加可删（`＋` 展开下拉 / 点 `×` 移除）
  - 右侧缩略图点一下即追加到「当前追加目标」，再点取消
  - 运行时按 7 秒轮播该状态下的多张图

### 2.3 配置结构

```json
{
  "mode": "v2",
  "alwaysOnTop": true,
  "scale": 1,
  "mapping": {
    "v1": { "idle": ["00","01"], "processing": ["13"], "pending": ["21"] },
    "v2": { "idle": ["Idle_01","01"], "processing": ["36"], "pending": ["24"],
            "done": ["13"], "error": ["33"],
            "idle_5": ["20"], "idle_15": ["18"], "idle_30": ["16"] }
  }
}
```

改完点「保存」→ 主进程写入 → **立刻下发给桌宠窗口**（映射与大小即时生效，不用重启）。

### 2.4 宿主桥（`window.petHost`）新增接口


## 三、拖动手感修复

### 3.1 根因：正反馈漂移

宿主模式下拖动桌宠 = 移动窗口。原先用**视口坐标**求增量：

```
dx = e.clientX - 上次 clientX
```

可窗口一旦跟着鼠标移动，**视口坐标本身也跟着变**——鼠标没动，clientX 却已经变了。
于是「窗口动 → 坐标变 → 又判定为位移」形成正反馈：**越拖越快，并持续往一个方向偏**（实测偏下）。

**修复**：宿主模式一律改用**屏幕坐标**（`e.screenX/screenY`，与窗口位置无关）求增量，
窗口位移与鼠标位移一一对应。拖拽起点在超过阈值时重新对齐一次，避免起手跳。

```js
if (hosted) {
  var ddx = sp.x - lsx, ddy = sp.y - lsy;   // 屏幕坐标增量
  lsx = sp.x; lsy = sp.y;
  window.petHost.move(ddx, ddy);
}
```

（浏览器内拖动仍走视口坐标 + 边界夹紧，未改动。）

### 3.2 摇晃幅度再收敛

拖动时另外加了「**停用摇晃动画**」：`.pet.dragging .sprite{animation:none}` ——
位移完全交给鼠标，立绘不再自己晃。同时把各状态的循环动画继续压低：

| 动作 | 上一轮 | 本轮 |
|---|---|---|
| 呼吸（待机） | 3px / 6.0s | **1.6px / 7.2s** |
| 处理中 | 2.2px / 0.22° / 2.8s | **1.3px / 0.12° / 3.6s** |
| 待确认（峰值） | 6px / 3.2s | **3px / 4.0s** |
| 空闲不满 | 2px / 0.35° / 3.6s | **1.1px / 0.18° / 4.4s** |
| 空闲生气 | 2.2px / 0.6° / 2.6s | **1.2px / 0.3° / 3.4s** |
| 互动反应 | 7px / 1.012× | **3.6px / 1.006×** |

自检里的幅度上限断言同步收紧到 **≤ 4px**（实测最大 3.6px）。

## 四、启动与约束

```bash
# 开发态
electron\run.cmd          # 或 ./run.sh

# 打包后的绿色版（启动最快，无需解压）
dist\miyo-pet-win32-x64\miyo-pet.exe

# 单文件便携版（一个文件即可分发；见 docs/08）
dist-single\miyo-pet-portable.exe
```

两个环境坑已封进启动器（详见 06 文档）：
`ELECTRON_RUN_AS_NODE=1`（主进程拿不到 app/ipcMain）、无可用 GPU（`MIYO_GPU=off` + `MIYO_NO_SANDBOX=1`）。
`MIYO_GPU` 在 `main.js` 里**默认就是 `off`**（软件渲染），所以双击即用、不必先设变量。

> **透明背景**：老师已确认**正常、无黑底**，故未做改动。
> 万一在别的机器上出现黑底，用 `set MIYO_GPU=on` 再启动（反之报 GPU 不可用时改回 `off`）。

> **一点说明**：我这边（执行沙箱）无法把窗口留在后台 —— 命令结束时子进程会被回收。
> 所以启动这一步仍需老师自己点一下 exe。
