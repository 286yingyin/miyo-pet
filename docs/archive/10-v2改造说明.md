## 一、三个 bug 的根因与修法

### bug1 · WorkBuddy 没有待办，桌宠却提示有

**根因（实测）**：`config.json` 里 `"scope":"all"` —— 桌宠把 `tasks\` 下**所有历史对话**的  
待办加总（当时 pending=4，全部来自 `e2cb725d`、`294ad3e9` 两个**别的对话**），而 WorkBuddy  
界面只显示当前对话。默认值本来是 `current`，是被持久化配置覆盖了。

**修复（三层）**：

| 层      | 改动                                                                                                                                                   | 位置                                                |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 一次性迁移  | 老配置 `scope=all` 自动改回 `current` 并写 `_v:1`；迁移动作记入变化日志                                                                                                  | `electron/main.js` `migrateConfig()`              |
| 会话判定加固 | `sessions\*.json` 按 sessionId **去重**（120 文件 → 26 条）；排除 `prewarm` / `interactive-<pid>` / Temp cwd / 无 tasks 目录；**滞后锁定**（心跳 120s 内不轻易改选会话，超时 5 分钟才重选） | `scripts/state-core.js` `resolveCurrentSession()` |
| 口径自曝   | 桌宠常显一枚「口径」胶囊（`仅当前会话` / `全部会话`），`全部` 时暖色——以后一眼就能看出数字口径                                                                                                | 两版 `pillScope`                                    |

修 `normalizeConfig()` 里 `cfg.scope !== 'v1'` 的笔误（应为 `'current'`）。

### bug2 · 半身模式（v1）显示不全

**根因（实测）**：窗口尺寸恒为 `240×620 × scale` 与模式无关，而 v1 桌宠固定 300px 宽 →  
横向被裁、纵向大片留白。

**修复**：窗口按模式区分。`WIN_BY_MODE = { v1:{w:320,h:420,petW:300}, v2:{w:240,h:620,petW:196} }`；  
`windowSize(mode,scale)` / `applyWindow({reload})`（右下角锚点保持；换页前 `setOpacity(0)`  
防旧尺寸闪一帧）。两版 CSS 的 `.pet/.sprite` 宽度改由 `--pet-w` 驱动，`check.js` 断言  
`--pet-w` 与 `WIN_BY_MODE.petW` 一致，防止再漂移。

**实测**：v1 → 窗口 320×420，v2 → 240×620，均正常载入。

### bug3 · 设置里差分预览过小

**根因（实测）**：图库 `minmax(44px,1fr)`，v2 竖图缩略图仅约 44×120px。

**修复**：右列 300→380px 并 sticky；缩略格 `minmax(44px→104px,1fr)`；右列上方新增  
**大图预览区**（约 380×240）—— 悬停缩略图即在预览区放大显示。原有「单击缩略图 = 追加/移除  
到当前状态」的 toggle 手感不变。

## 二、四项新功能

### N1 · 显示开关 + 进行中对话数

- 设置页新增「显示指标」区块：**操作（待批准）/ 任务（处理中）/ 待办 / 已空闲 / 进行中对话**  
  五枚胶囊逐项开关（`pillVisible`，关掉 = 整行消失）。
- 新数据 **进行中对话数**：`sessions\*.json` 中 `kind==='interactive'` 且心跳 <120s、  
  有 tasks 目录、cwd 非 Temp，按 sessionId 去重 → `PetSnapshot.conversations`  
  （复用会话判定已读的文件，**零额外 IO**）。
- **今日积分 / 剩余积分：本轮不做**（老师已定）。数据源结论存档：  
  `workbuddy.db` 表 `session_usage` 有 `used`（今日求和 ≈1,580,598）与 `credit_json`  
  （今日求和 ≈356.3）两套口径；**Electron 33 内置 Node 20 没有 `node:sqlite`**，读库需升级  
  Electron 35 或自研解析 —— 通道已在配置里留好（`usage:{enabled:false,cacheMs,dbPath}`），  
  以后接入时按 `credit_json` 口径做。

### N2 · 气泡位置与大小可调

配置 `bubble:{width, fontScale, offsetX, offsetY, align}`，页面 CSS 改变量驱动  
（`--bubble-w/--bubble-fs/--bubble-tail-x`）。`layoutBubble()` 按 `align` 计算归一化位置并  
夹在视口内，尾巴自动瞄准桌宠。设置页有 5 个控件 + 迷你预览。

### N3 · 每状态预览 + 台词自定义 + 语音通道预留

- 表情映射模块：每个状态行内嵌**已选差分缩略条**（28×28，可点在图库中定位）。
- **台词自定义**：配置 `lines:{v1:{mode:[...]},v2:{...}}`（一行一条，多条与表情同步轮播）；  
  未配置时回落内置台词，**完全向后兼容**。
- **语音通道（预留）**：配置 `voices` 字段可容纳官方语音文件路径（`ba-kivo-asset-fetch`  
  skill 可拿到美代官方语音直链，约 91 条 OGG，本轮未抓取）；页面暴露  
  `MiyoPet.playVoice(mode)`（现只派发 `CustomEvent('miyo-voice')`）、宿主通道  
  `petHost.speak({mode,text,file})`。**只留通道不实现播放**（素材尚未归档）。

### N4 · 整点播报（24 小时可分别设置）

- 配置 `hourly:{v1:{},v2:{"9":{on,lines,sprs,voice,ms}}}`，0–23 点各自一套（台词/表情/时长），  
  每套独立开关；未配置的小时走静默。
- 调度在**主进程**（`maybeChime()` 挂在 2s 兜底轮询末尾）；**宽限 10 分钟**  
  （`hourlyGraceMs`，超时只记账不播）；小时键 `YYYY-M-D-H` 去重；**重启不重播**——启动时从  
  变化日志找回最近一次播报的小时键；`powerMonitor.resume` 后补算。
- 页面端 `playChime(p)` 走既有反应层（带 `chime:true` 标记），**不重置空闲计时**；  
  宿主通道 `petHost.onChime`。
- **实测**：准点触发 ✓；迟到 39 分钟被宽限跳过 ✓；二次启动去重（1→0 次）✓；  
  清空 history 后恢复播报（证明去重真走日志）✓。

## 七、热修复记录（0.2.0 · 2026-10-12 深夜）

**事故**：v2 首次真机运行，立绘/气泡/胶囊**全部不显示**，但右键菜单正常；冷启动即空、重启无效。

**根因**：本轮新增的「防闪帧」机制在 `did-finish-load` 里调用 `win.setOpacity(1)`（冷启动也执行）。  
Windows 上对 `transparent:true` 窗口调 `setOpacity` 会把窗口切到 **layered 模式**；  
默认软件渲染（`MIYO_GPU=off`）下合成器从此不再出画面 —— 页面 JS 完整存活  
（所以右键菜单、鼠标命中、IPC 全正常），但像素永不绘制。v1 基线无此代码，故以前正常。

**修复**：

- 彻底移除两处 `setOpacity`（`applyWindow` 的置 0 与 `did-finish-load` 的恢复），  
  切换模式/改尺寸时接受可能的一帧旧内容闪现（透明窗口几乎不可见）
- `scripts/check.js` 新增回归护栏：**main.js 代码中 setOpacity 出现次数必须为 0**（剥注释后计数）
- 版本 `0.1.0 → 0.2.0`（便携产物名变为 `miyo-pet-0.2.0-portable.exe`，与可能残留的  
  旧 `0.1.0` exe 彻底区分）

**验证**：check.js 全过（含新护栏）、单测 29 项全过、绿色版/便携版重建后  
源码 md5 一致、双模式冷启动冒烟正常。最终目视由老师确认。

**教训（已记入长期备忘）**：透明窗口 + setOpacity + 软件渲染 = 永久停止绘制。

## 八、0.2.1 修复记录（2026-10-13 凌晨）

### 8.1 设置页空壳（所有调节功能失效）

**根因（node DOM 桩实测复现）**：`settings.html:811-814` 的  
`bindPill('vWorking','working', cfg.pillVisible)` 在**绑定时刻**解引用 `cfg`，而 `cfg` 要到  
`getConfig()` 回调才有值（当时还是 null）→ TypeError 炸断整个脚本 → 保存按钮、全部滑块/开关的  
监听器从未注册，`boot()/buildMap()/buildGallery()` 未执行，映射 UI/图库/24 小时格子连 DOM 都没有。  
preload、IPC 通道、字段映射均实测无恙。

**修复**：`bindPill` 改为 handler 内取值（`if (cfg) cfg.pillVisible[key] = …`）；三个分段点击器  
与大小滑块补 `if (!cfg) return;` 防御；DOM 桩复验加载期零异常。

### 8.2 模式切换闪烁 → 单页双模式（无缝衔接）

**根因**：切换走 `setBounds → loadFile`：旧内容在新视口错位/裁切 → 换页期间透明窗全空  
（桌宠消失 0.5~1s）→ 新页突现 + CSS 动画相位复位，三段叠加即「闪来闪去」。

**方案（老师选定：单页双模式；v1 升级到与 v2 同一套行为）**：

- `prototype/v2/index.html` 成为**唯一被 Electron 加载的页面**：`VERSETS` 素材表 +  
  `MAP_DEFAULTS`（v1/v2 各一套）+ `body[data-ver]` CSS 变量（--pet-w/--sprite-h/--pet-origin、  
  画廊宽高比）；`applyConfig` 检测 `cfg.mode` 变化即热切换（重置映射 → 重建映射 UI/画廊 →  
  仅预取 MAP+REACT+blink 引用的十几张图，**严禁全量预载 81 张**）。  
  v1 因此获得空闲生气等完整行为；`prototype/v1/index.html` 保留为浏览器预览壳。
- `electron/main.js`：`applyMode / config-save / config-reset` 全部去掉 reload 换页，  
  改为 `sendConfig()`（页面热切换）+ `applyWindow()`（只重设窗口尺寸，右下锚点不变）。
- `electron/paths.js`：`page(mode)` 固定返回单页（形参保留）。
- `scripts/check.js`：宽度基准断言改为从 `body[data-ver]` 两段提取；接口断言改为单页 15 键；  
  新增 VERSETS/MAP_DEFAULTS/verChanged/prefetchMapped/data-ver CSS 断言。

**验证**：check.js 全过（宽度 300/196 ⟷ 320×420 / 240×620、15 键、双模式符号）；  
单测 29 项全过；DOM 桩运行无异常；绿色版双模式冷启动冒烟（v1→320×420、v2→240×620、页面就绪）；  
0.2.1 包内 app-root 页面与源码 md5 一致。

**待老师目视**：① 设置页各控件生效；② 右键切 v1↔v2 桌宠不消失、仅淡入换素材 + 窗口尺寸平滑变化。

## 十八、0.2.11 闲置轮播根治：隐式台本0 无缝循环 + 休息期一律静默（2026-10-13）

### 18.1 现象与根因

## 二十二、0.2.15 设置页保存脱钩（首次生效、再改无效）根治 + 待机眨眼统一 99（2026-10-13）

## 四十二、0.3.22（版本不变）「已连接：0 个系列」根因修复（2026-10-14）

### 42.1 根因（一行代码）

webGatherPacks 的枚举链（v1/v2 目录遍历）是**异步**的，但函数末尾
