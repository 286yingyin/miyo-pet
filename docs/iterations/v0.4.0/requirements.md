# v0.4.0 需求与验收标准

状态：2026-10-15 用户批准开发，先在 Windows 验证，Mac 实机由用户后续补验。应用基线：`0.3.23` / `9ff3645`。`v0.4.0` 是本次迭代暂定编号，尚未升版。

关联：[总需求池](../../requirements/roadmap.md) · [技术方案](design.md) · [开发计划](plan.md) · [测试与验证](verification.md)

## 1. 本版目标

**Windows 保持可用，macOS 基础可用，接入 Codex 桌面端，角色切换保留各自配置。**

用户已确认优先 Codex 桌面应用。Codex CLI 的模拟或实测不能替代桌面端；接入入口先验证，未证明前不承诺某种技术路径已可行。

## 2. 用户场景

1. 现有 Windows 用户升级后，原来的美代设置、WorkBuddy 状态、语音、互动和提醒继续工作。
2. 未安装 WorkBuddy 的用户可以只使用 Codex 或纯摆宠；不会因为缺失 WorkBuddy 一直显示错误表情。
3. 用户在 Codex 桌面端开始工作，桌宠显示正在工作；需要批准 / 输入时有可解释的等待提示；完成、中断与失败分别处理。
4. Mac 用户能从原生构建产物启动、打开设置、播放音频并保存配置，重启后恢复；不需要写 `.app` 内部。
5. 用户在美代和本地角色包之间切换，再切回来，差分、台本、声音和显示配置仍属于对应角色。

## 3. 功能要求

| 验收编号 | 关联需求 | 本版必须达到的行为 |
| --- | --- | --- |
| AC-01 | REQ-BASE-01 | Windows 10/11 x64 保留开发启动、目录版 / portable 构建及现有主要功能；旧配置升级可恢复 |
| AC-02 | REQ-BASE-01、REQ-BASE-02 | 未配置 / 无可用 WorkBuddy 数据显示为未接入或待机；已接入后读取失败显示来源异常，不能冒充任务失败或完成 |
| AC-03 | REQ-BASE-02 | 宿主与页面缩放范围统一为 0.5–5；扫描支持的角色包都可在设置中列出并切换 |
| AC-04 | REQ-BASE-02、REQ-AGENT-01 | 关闭某 Agent 后停止其监听 / 轮询，不再由该来源触发状态或故障；重新开启后可恢复 |
| AC-05 | REQ-AGENT-01 | 可选择 WorkBuddy 或 Codex 作为当前来源；来源和接入状态可见；不同来源的数量、完成事件与等待信号不串用 |
| AC-06 | REQ-AGENT-02 | 在真实 Codex 桌面端验证开始、运行、完成、中断、失败、等待批准 / 输入及恢复，记录应用版本、平台、接口和不支持项；没有某类信号时必须明确评审缺口 |
| AC-07 | REQ-AGENT-02 | 桌宠收到来源事件后 5 秒内更新；重复 / 乱序 / 重启重放不重复庆祝、不让旧等待覆盖新状态；无法确认时显示未知，不编造 0 或完成 |
| AC-08 | REQ-PLAT-01 | 提供 macOS 原生启动、arm64 / x64 构建入口和检查步骤；本次 Windows 交付不要求 Mac 实机，构建 / 运行均分别标注，用户后续补验才标为通过 |
| AC-09 | REQ-PLAT-01 | Mac 的透明显示、拖动、菜单 / 设置、音频、配置保存、休眠恢复可用；应用重新启动和屏幕变化后窗口仍可找回 |
| AC-10 | REQ-PLAT-01 | 内置资源只读；外部角色包、配置和事件使用可写用户目录；中文、空格、`#` 等路径能加载，不向 `.app` 内写入 |
| AC-11 | REQ-CHAR-01、REQ-CHAR-02 | 至少用美代和一个本地 / 合成测试角色完成 A → B → A 与重启验证；分别保留角色映射、台本、语音、互动、整点 / 闲置配置及角色显示参数 |
| AC-12 | REQ-CHAR-01、REQ-CHAR-02 | 缺失差分仅在当前角色内回退；没有可用素材则提示包不可用；不自动借用美代图片、台词或语音填充其他角色 |
| AC-13 | REQ-CHAR-01、REQ-ENG-01 | 从旧配置迁移时有原始备份，迁移可重复且不丢未知字段；无效配置 / 角色包不会破坏已可用配置；可手动回退 |
| AC-14 | REQ-ENG-01、REQ-ENG-02 | 自动回归与平台实测有记录；打包产物单独验证；功能完成后同步实际功能说明、架构导览和本版验证结论 |

AC-06 是关键技术门槛：若桌面端无法提供某个必要事件，先记录复现、可获得的最小状态与替代方案，再评审调整该项；不得自行将目标降为 CLI 或仅“检测进程存在”。

## 4. 兼容规则

- 本版不更换 Electron / 原生 HTML 技术栈，不引入新的前端框架。
- WorkBuddy 现有状态内核先经适配器包装，原有 29 项状态断言保留；允许补足缺失来源与失败区分。
- 保留两种旧包布局 `packs/<角色>/{v1,v2}`、`packs/{v1,v2}/<角色>`，旧 `manifest.json` 只有 `label` 也能识别；冲突优先级由方案统一定义。
- 原配置迁移给升级前选中的角色；不能把用户现有角色台本强行归到美代，也不为每个新角色复制同一套美代台词。
- Windows 既有用户目录和自定义 packs 位置继续可用；Mac 使用用户数据目录。配置迁移前备份，失败时停止写回。
- 两种半身 / 全身模式继续保留，不改现有台本语义和用户自定义提醒内容。

## 5. 本版明确不做

完整多会话面板、DSH 正式接入、CPU / 内存 / 网络监控、静音时段、全屏智能隐藏、鼠标穿透、位置偏好管理、多屏吸附、角色包制作工具、Spine、番茄钟均在[需求池](../../requirements/roadmap.md)保留。

Mac 首版只保证基本窗口可用与屏外找回，不承诺跨所有全屏 Space 常驻。代码签名 / 公证、商店发布和自动更新不属于“本地基础可用”的完成条件；公开分发前必须另行明确签名状态及实际首次启动行为，不能把未签名产物描述为可直接公开安装的正式发行版。

## 6. 首版完成判定

1. AC-01～AC-14 在[验证记录](verification.md)有对应结果；未执行不能填通过。
2. Codex 桌面端事件可行性结论明确且关键状态通过实测；若需缩小支持范围，需求文档先记录评审结论。
3. 本次 Windows 两种产物实测通过，Mac 兼容实现与可执行验收步骤随 PR 提供；Mac 实机由用户后续补验，未实测架构和系统明确列出，不阻塞 Windows 交付。
4. 旧配置、旧包升级后不丢数据，功能分支可以独立回退。
5. 发布版本号、支持矩阵、用户说明与最终实现一致。

## 7. 决策与外部条件

| 项目 | 当前约定 | 对实施的影响 |
| --- | --- | --- |
| Codex 目标 | 桌面端优先，用户于 2026-10-15 确认 | 第一个里程碑必须验证真实桌面事件 |
| Mac 硬件 | 用户有 Mac，明确安排 Windows 开发后再切回 Mac 验证 | 本次先交付 Windows，Mac 待用户后续补验 |
| Mac 系统版本 | Electron 33.4.11 官方二进制支持 macOS Big Sur / 11 起；本项目计划先做 macOS 13+ 兼容验证 | 框架支持不等于桌宠已验证；变更 Electron 时重新核对 |
| Mac 架构 | arm64 / x64 均有构建目标，实测状态分别标注 | 至少一个架构实机通过，其余不得标为已验证 |
| 新角色素材 | 首版不承诺随包分发第二个游戏角色 | 用合成夹具自动测试，用户自有包本地验收 |
| 发布归属 | 个人 fork 开发，拟向上游分模块提 PR | 不需要等待上游写权限即可推进本地工作 |

框架平台信息参考 [Electron v33.4.11 README](https://github.com/electron/electron/blob/v33.4.11/README.md#platform-support)，不使用最新主分支的系统要求代替当前锁定版本。
